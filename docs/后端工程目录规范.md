# C-53 后端工程目录规范

## 1. 目标

后端采用单应用、按业务模块分包的结构。登录注册只是第一个业务模块，后续内容、评论、个人主页、通知等模块不得继续堆放到认证包下。

## 2. 顶层结构

```text
C-53_be
├── .mvn/maven.config
├── maven-settings.xml
├── pom.xml
└── src
    ├── main
    │   ├── java/com/c53
    │   │   ├── C53Application.java
    │   │   ├── common
    │   │   │   ├── ApiResponse.java
    │   │   │   ├── GlobalExceptionHandler.java
    │   │   │   └── support
```

## 3. 分层职责

| 目录 | 职责 |
|---|---|
| `common` | 跨模块复用的响应、异常、请求上下文和通用工具 |
| `config` | 应用级配置绑定 |
| `security` | JWT 解析、认证过滤器、Spring Security 配置 |
| `modules/<module>/controller` | HTTP 路由、请求参数提取、状态码 |
| `modules/<module>/dto` | 对外接口请求和响应模型 |
| `modules/<module>/model` | 模块内部行对象、领域模型 |
| `modules/<module>/repository` | 数据库访问，只在本模块使用 |
| `modules/<module>/service` | 业务编排、事务边界和外部依赖调用 |
| `modules/<module>/support` | 仅本模块使用的工具类 |

## 4. 依赖规则

1. 业务模块包名统一为 `com.c53.modules.<module>`。
2. 模块可以依赖 `common`、`config`、`security`，共享包不得反向依赖具体业务模块。
3. 模块之间不要直接注入对方的 Repository；需要跨模块能力时，优先通过对方的 Service 接口或事件协作。
4. 模块专属 Redis Key 必须带模块前缀，例如认证模块使用 `auth:rt:*`。
5. 模块数据库脚本放在 `src/main/resources/db/<module>/`，按模块独立演进。
6. 接口路径使用 `/api/v1/<module>/**`，避免所有接口都挂在 `/auth` 下。

## 5. 新增模块步骤

1. 创建 `com.c53.modules.<module>` 及 `controller/dto/model/repository/service/support` 子包。
2. 新增 `src/main/resources/db/<module>/<module>-schema.sql`。
3. 在 `application.yml` 的 `spring.sql.init.schema-locations` 中追加脚本。
4. Controller 使用 `/api/v1/<module>` 作为正式路径；如需要兼容旧路径，再增加过渡别名。
5. 单元测试放在 `src/test/java/com/c53/modules/<module>`。
6. 不复制认证模块的通用工具；需要复用时上移到 `com.c53.common`。

## 6. 当前认证模块

认证模块包：`com.c53.modules.auth`。

正式接口：

- `/api/v1/auth/**`
- `/api/v1/me`

兼容别名：

- `/auth/**`
- `/me`
- `/auth/me`
