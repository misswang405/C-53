# C-53 认证与密码重置开发文档

> 版本：1.1｜日期：2026-10-26｜状态：代码已实现；迁移未执行，真实环境联调与并发验收待完成
> 面向：前后端研发、测试、运维。配套：[需求文档](../需求文档/认证与密码重置需求.md)。

## 1. 现状与复用点

- `AuthController` 已增加公开 `POST /password/reset`，成功返回 204。
- `AuthUtils.normalizeScene` 与新库基线均支持 `register/login/reset_password`；存量数据库须另行迁移。
- 挑战校验仍使用 HMAC、过期、行锁、条件消费。`VerificationException` 由认证事务捕获并作为返回值提交，事务完成后再抛出，避免错误次数回滚；非验证业务异常正常回滚。
- 重置事务更新密码、全部旧会话/家族、设备账号重认证标记，并写入 `auth_cleanup_tasks`。提交后尝试 Redis 清理，后台任务指数退避重试。
- `JwtAuthenticationFilter` 调用 `AuthSessionGuard` 校验数据库会话和用户状态；已撤销 JWT 降级匿名，受保护路径拒绝访问。数据库查询失败返回 503，不放行认证。
- 前端保存并回传 `verificationId`，重置请求不自动刷新/重放；成功清理会话及私有数据，在途旧会话响应不能恢复认证上下文。
- 实际技术栈为 Java 21、Spring Boot 3.2.5、MyBatis-Plus 3.5.5、MySQL、Redis。不得按旧文档误写为纯 JDBC 实现。

## 3. 数据库设计与迁移

复用 `users.password_hash/password_algorithm/password_changed_at`、`user_contacts`、`auth_verification_challenges`、`auth_sessions`、`auth_token_families` 和 `auth_device_accounts`。

增量迁移必须扩展验证码场景约束与注释为 `register/login/reset_password`；`reset_password` 长度可容纳于现有 VARCHAR(16)。在 MySQL 8 的有效 CHECK 环境修改约束，在 5.7 兼容环境依赖应用校验并按实际版本选择语法，不能通发一份未经版本验证的 ALTER。

已新增 `auth_cleanup_tasks`：保存家族 ID、原过期时间、原因、状态、次数及下次重试时间；索引 `(status,next_retry_at,id)`，与密码重置同事务提交，不存原始 Token。默认每 30 秒扫描 100 条，失败按 5 秒至 1 小时退避，多实例重复清理幂等。完成记录暂不自动删除，PENDING 积压须监控。

人工迁移文件位于 `C-53_be/src/main/resources/db/auth/migration/`：

- `auth-cleanup-v2.3-mysql57.sql`：MySQL 5.7.8+。
- `auth-cleanup-v2.3-mysql80.sql`：MySQL 8.0.16+，需核对旧 CHECK 名称。
- `auth-cleanup-v2.3-notes.txt`：执行前检查、部署顺序、校验和回滚边界。

两份脚本只选匹配版本的一份；新库使用基线。MySQL 8.0.0—8.0.15 未覆盖。上述脚本均未执行。

`CREATE TABLE IF NOT EXISTS` 不会更新存量约束；上线必须执行独立增量迁移并验证。此文档不执行任何 SQL。

## 4. 接口实现

路径省略 `/api/v1`，新增 `POST /auth/password/reset`：

```json
{
  "identifierType": "EMAIL",
  "identifier": "member@example.com",
  "verificationId": "ver_example",
  "code": "123456",
  "newPassword": "ExamplePass123"
}
```

以上仅为示例，不用于生产默认密码。成功 204；失败使用现有 `ApiErrorResponse`，新错误码按需求文档落地。该接口不得因为当前浏览器已有过期 Access Token 而要求先登录，也不应通过自动刷新把验证码 401 当成会话过期反复提交；前端重置提交禁用刷新重试。

发送复用 A1：归一化 `RESET_PASSWORD`，同时接受现有 `identifierType/identifier` 和正式 `channel/target`。重置场景执行专属发送预算；未注册目标也创建无用户归属挑战，使用同结构脱敏响应和相同预算。登录/注册保留原有重发限制，不在本次扩展其他场景的总预算。

## 5. 事务、并发与会话撤销

### 5.1 推荐事务边界

1. 事务外做格式校验、发送/提交限流和密码编码；编码后不可记录原文。
2. 事务内锁定对应用户行，再按固定顺序锁定挑战，重新校验目标绑定及账号状态。
3. 挑战错误时，更新失败次数并返回一个失败结果对象，提交事务后再转换为 API 异常，避免运行时异常回滚计数；达到阈值置 FAILED。
4. 验证成功时，以条件更新消费 ACTIVE 挑战，更新密码哈希及 `password_changed_at`。
5. 吊销该用户全部有效会话和令牌家族；将所有设备保存账号标记需重新认证，不吊销其他用户共享的设备。
6. 同事务写 Redis 清理 outbox，提交后尝试立即清理；失败由任务重试。

不同用户或无账号挑战的分支也要遵循统一锁序，防死锁；遇死锁只能在未消费成功的完整事务边界有限重试。

### 5.2 阻止并发旧认证复活

仅“批量吊销现有会话”不足：旧密码可能已在事务外验证成功，随后才创建新会话。建议认证颁发路径统一锁用户行，并在锁内重新确认密码哈希/凭据版本、账号状态，再创建会话；刷新续期和账号切换也复核会话与设备账号资格。密码重置持相同用户锁，形成明确先后顺序。验证码登录同样受该边界约束。实现通过挑战 `createdAt` 与用户 `password_changed_at` 比较拒绝重置前创建的登录/重置挑战，不额外批量改写所有旧挑战状态。会话创建比较锁内密码哈希与先前校验快照；保存账号的重认证标记仅能在该用户锁内被成功认证路径解除。

受保护路由统一检查会话撤销，包含媒体读取、资料、消息、设置和个性化读取；合法但已撤销的 JWT 不得继续充当有权限用户。公开读取可以降级游客，受保护读取必须 401。若引入缓存，须定义同步失效机制和故障拒绝策略；首版优先数据库权威检查，不宣称缓存天然即时一致。

## 6. 安全与依赖失败

- 重置发送/校验限流是安全边界，不复用可能故障放行的普通业务限流策略；认证 Redis 不可用返回 503。
- MySQL 已提交吊销但 Redis 清理失败时，数据库会话检查必须仍拒绝旧 Token；清理 outbox 可恢复。
- 统一请求脱敏；不保存明文密码、验证码、原始 Refresh Token。
- 生产发送器不允许开发固定码；新增配置通过项目正常应用配置承载，不修改工具的 settings.json。

### 6.1 配置与部署限制

- 固定开发验证码默认关闭。仅本地显式设置 `SPRING_PROFILES_ACTIVE=dev`（或 test）和 `AUTH_VERIFICATION_DEV_MODE=true` 后允许；同时存在 prod/production 时仍拒绝固定码。
- 当前只有 `DevVerificationSender`，生产关闭开发模式后会拒绝投递。真实短信/邮件发送器及其凭证、模板、预算告警需另行接入，不能将本次实现描述为生产投递已可用。
- 重置发送默认 IP 10 次/分钟、100 次/天，目标 5 次/小时、10 次/天，另有重发冷却；提交默认 IP 10 次/分钟、目标 5 次/15 分钟。配置位于 `auth.limits`，对应环境变量见 `application.example.yml`。
- Redis 限流返回空结果或连接失败均拒绝，不故障放行。重置提交后清理失败不影响已完成的数据库撤销，后台继续补偿。

## 7. 前端改造

新增 `resetVerificationId`，收到挑战保存，切换目标/发送新码/重置成功时清空；请求增加 `verificationId`。重置成功调用 `clearSession` 并清理已登录用户的私有页面缓存，再打开登录页。提交期间防重复；更换目标后丢弃旧异步响应。倒计时以响应为准，失败不伪造成功。

## 8. 测试与验收

- 单元：场景归一化、密码规则、目标不匹配、挑战有效期/尝试上限、错误映射。
- 数据库集成：行锁并发消费、失败次数真实提交、密码与吊销原子性；必须真实 MySQL 验证，不只 mock mapper。
- 并发：重置与登录/验证码登录/切换/刷新交错，重置完成后无旧凭据会话复活。
- Redis 故障：提交前依赖失败不修改密码；提交后清理失败进入重试，旧 Access/Refresh 仍拒绝。
- HTTP：匿名可重置，重置请求不自动刷新重试；旧 JWT 访问各类受保护路径返回 401。
- 前端：手机/邮箱、修改目标、超时、倒计时、重复点击、成功后清理上下文。

## 9. 开发顺序、上线与回滚

1. 先补挑战测试、会话颁发并发锁和撤销检查；完成安全底座。
2. 增量迁移 → 后端重置接口 → 前端挑战回传 → 全链路安全测试。
3. 预发布检查短信邮件预算、固定码关闭、敏感日志脱敏和旧会话验证。
4. 灰度开放入口，监控失败率、吊销积压、认证延迟。
5. 回滚时关闭重置入口/写接口，保留已修改密码和已吊销会话，绝不恢复旧哈希或重新激活会话；扩展表和约束保留至兼容窗口结束。
