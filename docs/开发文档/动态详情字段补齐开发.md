# C-53 动态详情字段补齐开发文档

> 版本：1.0｜日期：2026-10-26｜状态：建议实施方案，未编码
> 面向：前后端研发与测试。配套：[需求文档](../需求文档/动态详情字段补齐需求.md)。

## 1. 当前代码依据

- 后端 `modules/post/dto/PostDtos.java` 的 `PostResponse` 已包含 `mediaType`、全部状态时间和四个真实互动字段。
- `PostServiceImpl.toResponses` 批量组装用户、话题、媒体与 `InteractionQueryService` 结果，不应改成逐条取评论的 N+1 查询。
- `ContentRules` 当前正文上限 600 码点、摘要 120 码点，不变更其发布规则。
- 前端 `services/api.js` 的 `normalizePost` 为 title/note/comments 做空值兜底，time 当前优先 displayTime 再回退 createdAt。
- `App.vue.openPost` 用 `Promise.all` 同时读取详情和评论，任何一个失败都会使成功结果未赋值。
- `PostDetailView.vue` 无条件输出标题与备注卡片；`replyingToId` 声明 Number，而接口 ID 为字符串，需随联调修正。

## 2. 技术决策

本期采用“基础动态 DTO + 独立评论分页 + 前端派生时间”。不新增 title/note 数据库列、不硬编码虚构备注、不让后端生成会陈旧的“几分钟前”。

保留 normalize 层对外部 title/note/displayTime 的兼容读取，但业务组件不要求其必填。后续若引入编辑标题/备注，单独扩展创建、更新、迁移和版本冲突测试。

## 4. 接口契约

`GET /posts/{id}` 返回现有 `PostResponse`，成功 200；不内嵌评论。

`GET /posts/{id}/comments` 返回：

```json
{
  "items": [{
    "id": "c_example",
    "author": {"id": "usr_example", "nickname": "示例用户"},
    "content": "示例评论",
    "createdAt": "2026-10-26T08:00:00Z",
    "replies": [],
    "repliesTruncated": false
  }],
  "nextCursor": null
}
```

上例为统一包装中的 data。`normalizeList` 只返回数组，会丢弃 nextCursor；分页页面必须先保存原始 payload 的 cursor，再 normalize items。不得误把 nextCursor 拼到每条评论。

## 5. 前端状态与异步处理

为当前详情维护 `postId/requestSeq/detailState/commentState/commentCursor/commentError`；状态限于本次页面，不污染全局帖子共享对象。

1. openPost 递增请求序号，初始化页面并保存目标 ID。
2. 两个请求可并发，但各自处理成功/失败；或使用 allSettled 后分别赋值，不能保持“一失败全部不更新”。
3. 每次赋值前检查序号与目标 ID；仅比较 postId 不足以区分同一动态的重复打开。
4. 详情成功确认状态：DRAFT/SCHEDULED 不展示公开讨论区，也不因 D5 拒绝而报整体错误。可先读取详情再决定是否发评论请求，减少无效调用。
5. 详情 404 清除旧敏感详情；评论错误保留正文，显示重试。
6. 加载更多时带 cursor、锁定 loading，按评论 ID 去重；同一层回复也按 ID 去重。
7. 评论新增与分页请求交错时合并已存在项，不用旧分页覆盖新评论；服务端 commentCount 是总数权威值。
8. 退出或切换账号时清理 liked/bookmarked 和私有详情缓存，不跨账号复用。

可在 request 层向 fetch 透传 AbortSignal，也可先采用序号丢弃；仅取消请求不能代替结果归属判断。

## 6. 时间与展示

时间工具输入 ISO 字符串、当前时间和状态，输出展示文本及完整本地时间。显示基准：PUBLISHED 用 publishedAt，否则 createdAt；scheduledAt 单独标明计划时间。未来值、缺失值、非法值走明确兜底。

相对时间在页面激活时按分钟刷新，并在卸载时清理定时器；不为每张动态卡片建立独立常驻定时器。note/title 仅非空时展示；保留文章可访问名称。正文仅用文本插值，不使用 v-html。

## 7. 后端约束与跨模块依赖

- 不修改已有 create/update/publish/schedule 行为及 optimistic version。
- 保留批量互动查询；评论截断由现有 D5 决定，前端不宣称已加载所有回复。
- 设置隐私模块上线后，详情、评论、feed、收藏需统一走可见性判断，不能只在主页过滤。
- 基础 DTO 字段存在与字段业务必填分别测试；topic/null 媒体尺寸都应被允许。

## 8. 测试方案

| 类型 | 用例 |
|---|---|
| 契约 | 当前 DTO 无 title/note/comments/displayTime 时正常；额外字段仍兼容 |
| 时间 | 跨 UTC/本地日界、夏令时环境、未来定时、编辑、空值和非法字符串 |
| 异步 | 详情成功评论失败；反向失败；A/B 快速切换；同 ID 重入；卸载后返回 |
| 评论 | cursor 续页、去重、截断提示、总数大于已加载数、发送与续页交错 |
| 权限 | 草稿作者、非作者、游客、删除、切账号后的缓存清理 |
| 安全 | HTML 文本不执行，外部媒体 URL 沿用既有安全策略 |

测试数据用确定时钟；不要把“刚刚”依赖真实测试执行时间。

## 9. 实施顺序与发布

先加契约/时间测试，再拆异步状态、条件展示和评论分页，最后做真实接口联调。前端构建及后端相关回归测试通过后灰度发布。无需数据库迁移；回滚恢复前端旧版即可，后端保持兼容。不在此文档编写阶段声称已运行应用或测试。
