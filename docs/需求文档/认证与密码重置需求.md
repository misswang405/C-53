# C-53 认证与密码重置需求文档

> 版本：1.1｜日期：2026-10-26｜状态：代码已实现，真实环境验收待完成
> 面向：产品、研发、测试。范围：接口清单 A1 的重置场景与 A7。
> 配套：[开发文档](../开发文档/认证与密码重置开发.md)、[接口清单](../接口文档/接口清单.md)。本文补充既有认证能力，不重做登录注册。

## 1. 背景与目标

实施前前端已有重置表单，但后端缺少重置场景和路由。现已补齐 `scene=RESET_PASSWORD`、`POST /auth/password/reset` 及前端挑战回传、会话撤销和失败补偿代码；存量数据库迁移未执行，真实短信/邮件通道和端到端验收仍需部署环境验证。

目标：通过已验证的手机号或邮箱找回密码；成功后旧密码、所有旧会话及设备免密切换资格失效，用户使用新密码重新登录。不得通过不同提示直接暴露账号是否注册。

## 2. 范围与角色

- 游客和已登录用户均可使用找回密码流程，证明联系方式持有权后才能修改对应账号密码。
- 支持中国大陆手机号、邮箱，与当前认证规范化规则一致。
- 本期不做联系方式换绑、用户名找回、账号注销、第三方账号找回和人工申诉。
- 不向禁用或已删除账号签发新会话；密码找回不能解除封禁。

## 3. 用户流程

1. 选择手机号或邮箱，输入接收地址，发送重置验证码。
2. 页面展示脱敏目标和倒计时，保存 `verificationId`；更换目标清除已有挑战和验证码。
3. 输入六位验证码、新密码及确认密码。
4. 后端验证挑战的场景、目标、状态、有效期和尝试次数，完成密码更新及旧会话吊销。
5. 成功返回 204，页面清除本地会话和敏感表单，回到密码登录；不自动登录。
6. 网络失败不能宣称成功，也不能自动重复提交；提示用户尝试新密码登录或重新获取验证码。

## 4. 接口需求

所有路径省略 `/api/v1`。成功及错误包装沿用现有规范；204 无响应体。

### 4.1 发送重置验证码

`POST /auth/verification-codes`，公开访问，成功 202。

| 字段 | 约束 |
|---|---|
| scene | `RESET_PASSWORD`，后端归一化为 `reset_password` |
| identifierType | `PHONE` / `EMAIL` |
| identifier | 目标联系方式，服务端规范化后校验 |

响应复用 `verificationId/channel/maskedTarget/expiresIn/resendAfter/resendAfterSeconds`。兼容 `channel/target` 请求字段，不另建发送通道。

未注册目标采用与正常目标相同的响应结构、倒计时和通用提示，不能返回“账号不存在”。可创建无账号归属的真实挑战并投递验证码，但必须受目标/IP/每日预算约束，防止滥用短信邮件；不能仅靠前端倒计时限流。该策略不是对时序侧信道的绝对消除，测试需检查明显差异。

### 4.2 重置密码

`POST /auth/password/reset`，公开访问，成功 204。

| 字段 | 必填 | 约束 |
|---|---|---|
| identifierType | 是 | `PHONE` / `EMAIL` |
| identifier | 是 | 与发送挑战时一致 |
| verificationId | 是 | 本次重置验证码挑战 ID；需补齐前端保存与回传 |
| code | 是 | 六位数字，兼容当前前端命名 |
| newPassword | 是 | 至少 8 位，同时含字母和数字；沿用现有密码校验和长度上限 |

确认密码仅供前端校验，不发送。不得允许以 LOGIN/REGISTER 场景验证码重置密码，也不得自动使用其他场景的最新挑战。

## 5. 核心规则

- 使用现有密码编码器保存哈希，密码和验证码明文不落日志、不入审计详情。
- 同一挑战最多成功一次；错误次数必须真实累计，不能因事务回滚归零。
- 目标未注册、挑战不匹配、已过期或已消费时使用通用验证失败提示；内部保留原因供排查。
- 密码更新、挑战成功消费、全部认证会话吊销和设备账号 `reauthRequired=true` 必须在同一数据库事务内完成。
- 成功后其他设备旧 Access Token 也不能继续访问需登录资源；仅轮换 Refresh Token 不满足要求。
- 不撤销共用设备上的其他用户账号或整个设备 Cookie。
- 登录、刷新和账号切换与重置并发时，重置前凭据不能在重置后生成有效新会话。
- 建议初始限流：发送沿用认证通道限制并增加重置专属预算；提交每 IP 10 次/分钟、目标 5 次/15 分钟。数值为设计默认值，须配置化并通过实际流量评估。

## 6. 异常与安全

| HTTP / 错误码（设计） | 用户提示及行为 |
|---|---|
| 400 VALIDATION_ERROR | 字段格式不正确，定位表单错误 |
| 400 PASSWORD_POLICY_VIOLATION | 新密码不符合要求 |
| 401 INVALID_VERIFICATION_CODE | 验证失败，请检查验证码或重新获取 |
| 429 RATE_LIMITED | 操作频繁，按 `details.retryAfter` 等待 |
| 503 SERVICE_UNAVAILABLE | 服务暂不可用，保留输入但不保存敏感内容到浏览器存储 |

限流和依赖不可用时不得放行密码修改；生产环境禁止固定验证码。与验证码有效期、最大尝试次数相关的规则复用现有配置，不在页面硬编码新的权威值。

## 7. 验收标准

- [ ] 手机、邮箱均可完成发送 → 重置 → 新密码登录，旧密码无法登录。
- [ ] 前端回传正确 `verificationId`；更换目标后旧挑战不能继续使用。
- [ ] 登录验证码、注册验证码、他人挑战、过期及已使用挑战均被拒绝。
- [ ] 连续错误达到上限后，即使再次输入正确验证码也不能通过。
- [ ] 两个请求并发使用同一挑战，仅一个成功。
- [ ] 成功后所有旧 Access/Refresh Token、设备快捷切换均失效；其他用户账号不受影响。
- [ ] 重置与密码登录、验证码登录、刷新、账号切换并发，旧认证上下文不能复活。
- [ ] 未注册目标不出现明确账号存在性提示，发送预算和限流同样生效。
- [ ] 数据库失败不产生“密码已改但旧会话仍有效”的状态；Redis 清理失败可补偿且不能绕过数据库吊销结果。
- [ ] 不在请求日志、浏览器持久存储及监控标签记录密码、验证码、完整手机号邮箱。

## 8. 交付与非功能要求

交付包含接口实现、重置场景数据库增量迁移、前端挑战保存、会话撤销联调和并发安全测试。上线需监控发送失败、验证失败、限流命中及吊销清理积压，不以包含敏感目标的高基数标签统计。
