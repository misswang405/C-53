# C-53 互动与收藏需求文档（PRD）

> 状态：初稿，待评审  
> 版本：1.0  
> 日期：2026-10-26  
> 模块：接口清单 3.4 互动与收藏（D1～D9）  
> 依据：`docs/接口文档/接口清单.md` 第 3.4 节、`C-53_fe/src/services/api.js`、`App.vue`、`PostDetailView.vue`、现有动态发布与社区发现模块。

## 1. 文档目的

本文档用于明确点赞、收藏、评论、回复、分享记录和我的收藏列表的业务目标、交互规则、接口契约、权限边界及验收标准，作为后端开发、前端联调和测试验收的共同依据。

本模块不改变动态的发布状态机；互动对象仅限已公开且未删除的动态。互动数据需要被首页信息流、动态详情和个人收藏页消费。

## 2. 现状与问题

### 2.1 当前实现

- 前端接口方法已经预留：
  - `api.js` 中存在点赞、收藏、评论、回复、分享和收藏列表方法。
  - `App.vue` 已实现对应的按钮交互、登录拦截、评论追加和分享失败静默处理。
  - `PostDetailView.vue` 已展示点赞、讨论、分享、收藏和二级回复界面。
- 后端当前只有 `PostResponse` 中的互动占位字段：`likeCount`、`likedByMe`、`bookmarkedByMe`、`commentCount`，返回值固定为 `0 / false`。
- 后端尚未实现互动模块的 Controller、Service、Repository、数据表和权限规则。

### 2.2 主要问题

1. 用户点击点赞、收藏、评论等按钮时，后端接口返回 404。
2. 多端或并发点击时，前端不能得到服务端最新状态，容易出现按钮状态和计数不一致。
3. 动态详情无法加载评论和二级回复。
4. 收藏页无法读取用户收藏过的动态。
5. 互动数据未进入信息流和动态详情，推荐模块也无法使用真实互动指标。

## 3. 目标与成功标准

### 3.1 产品目标

- 登录用户可以对已发布动态点赞、取消点赞、收藏和取消收藏。
- 任何用户可以查看公开动态的评论；登录用户可以发表评论和回复评论。
- 评论列表一次返回一级评论及其二级回复，前端不需要为每条评论单独请求回复。
- 登录用户可以查看自己的收藏动态，并使用游标继续加载。
- 分享行为只做统计记录，不阻塞系统分享流程。
- 所有写操作返回明确、可用于前端回写的最新状态。

### 3.2 成功标准

| 指标 | 目标 |
|---|---|
| 点赞/取消点赞状态一致性 | 接口返回的 `active` 和 `count` 可直接覆盖前端状态 |
| 收藏状态一致性 | 接口返回的 `active` 可直接覆盖前端状态 |
| 重复操作 | 重复点赞、重复收藏不重复增加计数，接口保持幂等 |
| 评论可见性 | 评论列表只返回公开且未删除动态的评论 |
| 回复层级 | 最多两级：评论 + 回复；禁止回复回复 |
| 信息流一致性 | 点赞数、当前用户点赞状态、收藏状态、评论数与数据库最终状态一致 |
| 性能 | 点赞/收藏 P95 ≤ 200ms；评论列表 P95 ≤ 300ms；收藏列表 P95 ≤ 300ms |
| 可用性 | 互动写入成功率 ≥ 99.5%；分享统计失败不影响系统分享 |

## 4. 角色与权限

| 角色 | 点赞/收藏 | 查看评论 | 发布评论/回复 | 查看我的收藏 |
|---|---|---|---|---|
| 游客 | 不允许 | 允许公开动态 | 不允许 | 不允许 |
| 登录用户 | 允许操作公开动态 | 允许 | 允许，受互动权限设置约束 | 允许 |
| 动态作者 | 可操作自己的公开动态 | 允许 | 允许 | 同登录用户 |
| 被禁用用户 | 不允许新增互动 | 仅按系统公开访问规则 | 不允许 | 不允许 |

说明：

- 本期不增加管理员角色和审核后台。
- 动态必须同时满足 `status = PUBLISHED`、`deleted_at IS NULL`，才允许产生新的点赞、收藏、评论和分享记录。
- 草稿、定时动态、已删除动态对非作者统一视为不存在，返回 `404 POST_NOT_FOUND`。
- 已存在的互动数据不会因动态暂时不可见而对外返回。
- 评论权限本期默认使用 `social.comments = EVERYONE` 的行为；设置模块上线后，服务端按评论权限配置拦截 `FOLLOWING`、`MUTUAL` 和 `NONE`。

## 6. 核心业务规则

### 6.1 点赞

1. 只有登录用户可以点赞。
2. 同一用户对同一动态最多存在一条点赞记录。
3. `PUT` 表示点赞，已点赞时重复调用仍返回 `active=true`，不重复增加数量。
4. `DELETE` 表示取消点赞，未点赞时重复调用仍返回 `active=false`，不减少数量。
5. 点赞成功返回最新 `count`，前端不得根据本地旧值自行推算最终数量。
6. 点赞数必须大于或等于 0；并发删除不能将计数减为负数。

### 6.2 收藏

1. 只有登录用户可以收藏。
2. 同一用户对同一动态最多存在一条收藏记录。
3. `PUT`、`DELETE` 具备幂等性，重复调用返回当前最终状态。
4. 收藏不影响动态的点赞数和评论数。
5. 收藏动态默认只对收藏者本人可见；本期不提供公开收藏夹。
6. 取消收藏后，动态从下一次 `/me/bookmarks` 查询中消失。

### 6.3 评论

1. 评论内容为纯文本，不解析 HTML，不执行 Markdown。
2. 去除首尾空白后，内容长度为 1～500 个 Unicode 码点。
3. 禁止 `\u0000` 等控制字符；保留普通换行，但前端默认以单行输入展示。
4. 评论必须绑定到已发布动态，作者本人也可以评论自己的动态。
5. 评论列表按一级评论创建时间倒序排列；同一时间按评论 ID 倒序稳定排序。
6. 每条一级评论的回复按创建时间正序排列，便于阅读对话顺序。
7. 回复只能指向一级评论；如果 `parentId` 已经是回复，返回 `400 INVALID_COMMENT_PARENT`。
8. 评论数包含一级评论和二级回复。新增评论或回复成功后都增加 1。
9. 本期不提供删除接口，因此用户提交后不能通过公开 API 修改或删除评论；异常内容由后续审核模块处理。
10. 评论列表建议限制单次返回最多 50 条一级评论，每条最多返回 20 条回复；超出回复在本期返回 `repliesTruncated=true`，后续版本再增加回复分页。

### 6.4 分享记录

1. 分享接口只记录用户主动触发的分享行为，不代表第三方平台分享成功。
2. 当前支持渠道：`WECHAT`、`QQ`、`DOUYIN`。
3. 只有登录用户可以上报分享事件。
4. 分享接口成功返回 `204 No Content`，前端不依赖响应内容。
5. 前端分享失败或后端记录失败时，不得阻塞系统分享；前端静默忽略记录接口异常。
6. 分享行为需要限流，但不要求严格去重；同一用户多次分享可以产生多条统计记录。

### 6.5 动态互动字段

信息流和动态详情中的 `PostResponse` 必须返回以下字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `likeCount` | number | 当前动态点赞总数 |
| `likedByMe` | boolean | 当前登录用户是否点赞；游客恒为 `false` |
| `bookmarkedByMe` | boolean | 当前登录用户是否收藏；游客恒为 `false` |
| `commentCount` | number | 一级评论和二级回复总数 |

批量查询动态列表时必须批量获取互动数据，禁止对每条动态分别查询点赞、收藏和评论状态。

## 7. 接口契约

### 7.1 通用约定

- 基础路径：`/api/v1`。
- 请求和响应编码：`application/json; charset=utf-8`。
- 鉴权：登录接口携带 `Authorization: Bearer <accessToken>`。
- 成功响应统一包装为：

```json
{
  "code": "OK",
  "data": {},
  "requestId": "req_xxx"
}
```

- 错误响应统一为：

```json
{
  "code": "CONTENT_EMPTY",
  "message": "评论内容不能为空",
  "details": [],
  "requestId": "req_xxx"
}
```

- 时间统一使用 ISO 8601 UTC 字符串。
- 下文路径省略 `/api/v1` 前缀。

### 7.2 D1 点赞

#### `PUT /posts/{id}/like`

- 鉴权：需要登录。
- 成功：`200 OK`。
- 语义：确保当前用户已点赞。

响应：

```json
{
  "code": "OK",
  "data": { "active": true, "count": 129 },
  "requestId": "req_xxx"
}
```

### 7.3 D2 取消点赞

#### `DELETE /posts/{id}/like`

- 鉴权：需要登录。
- 成功：`200 OK`。
- 语义：确保当前用户未点赞。

响应：

```json
{
  "code": "OK",
  "data": { "active": false, "count": 128 },
  "requestId": "req_xxx"
}
```

### 7.4 D3 收藏

#### `PUT /posts/{id}/bookmark`

- 鉴权：需要登录。
- 成功：`200 OK`。
- 语义：确保当前用户已收藏。

响应：

```json
{
  "code": "OK",
  "data": { "active": true },
  "requestId": "req_xxx"
}
```

### 7.5 D4 取消收藏

#### `DELETE /posts/{id}/bookmark`

- 鉴权：需要登录。
- 成功：`200 OK`。
- 语义：确保当前用户未收藏。

响应：

```json
{
  "code": "OK",
  "data": { "active": false },
  "requestId": "req_xxx"
}
```

          {
            "id": "cmt_01K7...",

兼容要求：前端 `normalizeList` 已兼容数组和 `{items, nextCursor}` 两种结构；后端正式契约采用对象结构。

### 7.7 D6 发表评论

#### `POST /posts/{id}/comments`

- 鉴权：需要登录。
- 成功：`201 Created`。
- 请求体：

```json
{ "content": "这段观察很有启发。" }
```

响应 `data` 为新评论对象，结构与 D5 的评论项一致，`replies` 返回空数组。

### 7.8 D7 回复评论

#### `POST /comments/{id}/replies`

- 鉴权：需要登录。
- 成功：`201 Created`。
- 路径中的 `{id}` 必须是一级评论 ID。
- 请求体：

```json
{ "content": "谢谢你的回应。" }
```

响应 `data` 为新回复对象，结构与 D5 的评论项一致，`replies` 返回空数组。

### 7.9 D8 分享事件

#### `POST /posts/{id}/share-events`

- 鉴权：需要登录。
- 成功：`204 No Content`。
- 请求体：

```json
{ "channel": "WECHAT" }
```

服务端只校验动态公开状态、渠道枚举和请求频率，不返回统计数量。

### 7.10 D9 我的收藏

#### `GET /me/bookmarks`

- 鉴权：需要登录。
- 成功：`200 OK`。
- 参数：

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---:|---:|---|
| `limit` | int | 否 | 20 | 1～50，超过按 50 处理 |
| `cursor` | string | 否 | null | 上一页返回的游标 |

响应：

```json
{
  "code": "OK",
  "data": {
    "items": [
      {
        "id": "pst_01K5...",
        "author": {},
        "topic": { "id": "tpc_01K5...", "name": "技术" },
        "content": "收藏的动态正文",
        "summary": "收藏的动态摘要",
        "mediaType": null,
        "media": [],
        "status": "PUBLISHED",
        "publishedAt": "2026-10-26T08:30:00Z",
        "createdAt": "2026-10-26T08:30:00Z",
        "ownedByMe": false,
        "likeCount": 12,
        "likedByMe": true,
        "bookmarkedByMe": true,
        "commentCount": 3
      }
    ],
    "nextCursor": "MTc2MTQ2..."
  },
  "requestId": "req_xxx"
}
```

排序固定为 `bookmarked_at DESC, post_id DESC`。动态被删除后不再出现在收藏列表中；历史收藏关系可以保留，也可以在删除事务中解除，但接口对外结果必须一致。

## 8. 错误码

| HTTP | code | 使用场景 | 前端处理 |
|---:|---|---|---|
| 400 | `VALIDATION_ERROR` | 参数格式错误、字段缺失 | 展示 `message` |
| 400 | `CONTENT_EMPTY` | 评论只有空白 | 展示“评论内容不能为空” |
| 400 | `CONTENT_TOO_LONG` | 评论超过 500 个码点 | 展示长度提示 |
| 400 | `INVALID_COMMENT_PARENT` | 尝试回复二级回复 | 提示只能回复一级评论 |
| 400 | `INVALID_SHARE_CHANNEL` | 分享渠道不支持 | 静默忽略或记录日志 |
| 401 | `UNAUTHORIZED` | 写操作或收藏列表未登录 | 引导登录 |
| 403 | `FORBIDDEN` | 用户状态不允许互动 | 展示无权限提示 |
| 403 | `COMMENT_NOT_ALLOWED` | 动态评论权限不允许 | 展示评论关闭提示 |
| 404 | `POST_NOT_FOUND` | 动态不存在、未公开或已删除 | 刷新详情或返回列表 |
| 404 | `COMMENT_NOT_FOUND` | 评论不存在或已删除 | 刷新评论列表 |
| 409 | `INTERACTION_CONFLICT` | 极少数状态冲突 | 重新获取最新状态 |
| 429 | `RATE_LIMITED` | 互动频率超过限制 | 展示稍后重试 |
| 503 | `SERVICE_UNAVAILABLE` | 数据库或关键依赖不可用 | 保留当前页面状态 |

点赞和收藏的重复调用不返回冲突错误，必须按幂等成功处理。

## 9. 前端交互要求

### 9.1 点赞与收藏

- 点击前先判断登录状态；未登录调用现有登录弹窗，不发起写请求。
- 请求成功后使用响应中的 `active`、`count` 覆盖本地对象，不根据旧值推算。
- 请求失败保留原状态并提示后端中文 `message`。
- 收藏成功后将动态加入收藏列表；取消收藏后从当前收藏列表移除。
- 按钮应避免重复提交；请求结束前可禁用当前按钮。

### 9.2 评论与回复

- 打开动态详情时并行请求动态详情和评论列表。
- 评论发表成功后将返回的新评论追加到一级评论列表，并将 `commentCount` 加 1。
- 回复发表成功后追加到对应评论的 `replies[]`，并将 `commentCount` 加 1。
- 评论输入为空时禁止提交；接口错误不清空输入框。
- 评论加载失败不应阻塞动态正文展示，可显示“评论暂时无法加载”和重试入口。

### 9.3 分享

- 前端先调用分享能力，再异步上报 D8；推荐使用 `void api.recordShare(...).catch(() => {})`。
- D8 失败不能阻止系统分享，也不显示阻塞式错误弹窗。

## 11. 验收标准

### 11.1 功能验收

- [ ] 游客查看公开动态评论列表返回 200。
- [ ] 游客点赞、收藏、发表评论、分享和访问 `/me/bookmarks` 返回 401。
- [ ] 点赞成功返回 `active=true` 和最新 `count`。
- [ ] 重复点赞不会增加两次计数。
- [ ] 取消未点赞动态不会出现负数计数。
- [ ] 收藏和取消收藏重复请求保持幂等。
- [ ] 动态详情和 Feed 返回真实互动字段。
- [ ] 评论内容为空或超过 500 个码点时返回明确错误。
- [ ] 评论列表包含一级评论和二级回复。
- [ ] 回复二级回复被拒绝。
- [ ] 评论数包含评论和回复。
- [ ] 分享记录返回 204，记录失败不阻塞前端分享。
- [ ] 收藏列表按收藏时间倒序并支持游标分页。
- [ ] 删除动态后，详情、评论和收藏列表均不再暴露该动态。

### 11.2 并发与安全验收

- [ ] 同一用户并发点赞最终只有一条点赞记录。
- [ ] 多用户同时点赞，计数等于实际有效点赞记录数。
- [ ] 同一用户并发取消点赞，计数只减少一次。
- [ ] 使用他人动态 ID 不能绕过公开状态和删除状态校验。
- [ ] 不能通过评论 ID 回复另一条动态的评论。
- [ ] 不能通过接口创建三级回复。
- [ ] 收藏列表不会返回其他用户的收藏关系。
- [ ] 评论、分享和互动查询均有用户维度/IP 维度限流。
- [ ] 日志不包含 Token、评论全文和用户隐私字段。
