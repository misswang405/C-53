# C-53 个人资料与关注需求文档

> 版本：1.0｜日期：2026-10-26｜状态：实施前设计，尚未实现
> 面向：产品、研发、测试。范围：接口清单 F1–F9。
> 配套：[开发文档](../开发文档/个人资料与关注开发.md)、[设置与隐私需求](设置与隐私需求.md)。

## 1. 背景与目标

前端已有个人主页、资料编辑、头像上传、成员主页和粉丝/关注面板，但相关后端路由尚未实现。认证 `/auth/me` 只提供有限用户资料；关注查询当前是 Noop 占位，因此关注流和推荐排除逻辑没有真实关系数据。

目标：完成个人资料与关注闭环，驱动真实统计、关注信息流和推荐创作者过滤，并为隐私与私信提供统一关系依据。不得将认证联系方式当成普通资料任意改写。

## 2. 范围和边界

### 本期包含

- 自己完整资料查询、资料编辑、头像上传。
- 他人公开主页与已发布动态，按权限过滤。
- 自己的粉丝和关注列表，关注/取消关注及双向关系。
- 动态数、粉丝数、关注数真实统计，空状态、加载错误和分页。

### 本期不包含

- 手机邮箱换绑、实名认证、人脸核验、头像审核后台。
- 公开收藏夹、查询任意用户粉丝列表的新接口、浏览量去重统计系统。
- 自动互相关注、关注审批、付费关注、粉丝分组。
- 从主页发起私信由私信模块负责接入，本模块提供用户 ID 和入口位置。

## 3. 资料字段规则

| 字段 | 规则 |
|---|---|
| nickname | 必填，去首尾空白后 1–20 个 Unicode 码点，沿用注册规则 |
| username | 必填，规范化为小写，3–24 位字母/数字/下划线/短横线，全局唯一 |
| realName | 可空，最多 50 码点；只是自填资料，不代表实名认证，仅本人可见 |
| bio | 可空，最多 300 码点，纯文本 |
| gender | PRIVATE / MALE / FEMALE / CUSTOM；本期 CUSTOM 只存枚举，不提供额外文本 |
| birthDate | 可空，YYYY-MM-DD，不晚于当天；默认仅本人可见，不作为年龄认证 |
| region / city | 可空，分别最多 64 码点 |
| address | 可空，最多 200 码点，仅本人可见 |
| profession | 主页沿用现有值；当前编辑表单不增加职业编辑，后续单独扩展 |
| phone / email | 本人可读取，按现有认证数据返回；普通资料接口不得变更绑定 |
| avatarUrl | 由头像上传接口生成，不能通过资料 PATCH 写任意 URL |

长度除 username 外均按码点计数。除明确仅本人字段外，他人只返回公开展示字段；出生日期、真实姓名、详细地址、手机号邮箱不能借用户摘要或列表泄露。

## 4. 用户流程

1. 进入自己的主页，读取 F1 和我的动态；统计不再依赖 normalize 默认 0 或硬编码示例数。
2. 打开编辑页，保存本人资料；失败保留草稿，成功以服务器返回覆盖本地资料。
3. 头像单独选择图片上传，成功立即生效，关闭资料编辑不撤销头像；页面需明确此语义。
4. 打开成员主页，同时查询资料与其已发布动态；隐藏、删除或不存在时不残留上一人的信息。
5. 点击关注/取消关注，以服务端 `following/followsMe` 回写按钮；同步影响粉丝/关注列表和统计。
6. 打开粉丝或关注列表，按游标加载更多；空列表与加载失败分开呈现。

## 5. 接口需求

以下均省略 `/api/v1`，除特别说明外返回 200 + 统一包装。

| 编号 | 方法与路径 | 请求与响应 |
|---|---|---|
| F1 | GET /me/profile | 需登录；完整资料 + stats |
| F2 | PATCH /me/profile | 需登录；提交可编辑资料；返回完整本人资料 |
| F3 | POST /me/avatar | 需登录；multipart file；返回 avatarUrl |
| F4 | GET /users/{id} | 可选登录；公开资料 + relationship + 可展示统计 |
| F5 | GET /users/{id}/posts | 可选登录；limit 默认 20/最大 50、cursor；返回 items/nextCursor |
| F6 | GET /me/followers | 需登录；limit/cursor；返回用户摘要 items/nextCursor |
| F7 | GET /me/following | 同上 |
| F8 | PUT /users/{id}/follow | 需登录；幂等关注；返回 following/followsMe |
| F9 | DELETE /users/{id}/follow | 需登录；幂等取消；返回 following/followsMe |

F2 为字段级 PATCH：未传字段保留；允许清空的字段传 null；nickname/username 不可清空。现有前端每次传完整表单仍可兼容。phone/email 若传与当前相同值可忽略；任何真实变更（含清空）返回 `CONTACT_CHANGE_REQUIRES_VERIFICATION`，前端应改为只读且不提交。

本人 stats：`postCount/followerCount/followingCount/viewCount`。postCount 只统计未删除已发布动态；viewCount 当前无数据来源，返回 null 并显示“暂未统计”，禁止伪造浏览量。公开主页只返回允许披露的统计，不返回私有字段。

## 6. 关注与权限

- 禁止关注自己；不存在、删除或停用用户不能新增关注。
- 同一有向用户对只有一条有效关系。重复 PUT/DELETE 不重复计数。
- `following` 表示我关注对方，`followsMe` 表示对方关注我；两者均为 true 时 MUTUAL。
- `FRIENDS` 在本项目统一指互相关注，不另建好友系统。
- 拉黑任一方向生效时禁止新增关注；取消关注仍允许，避免用户无法退出已有关系。
- 关注不等于获得读取权限。私密模式/主页权限按设置模块判断；不引入关注申请审批。
- 自己始终可通过 `/me/*` 查看自己的资料与列表；他人资料/动态按独立权限判断，不以“主页可见”推导“所有动态可见”。
- 成员动态接口只返回已发布内容，作者查看草稿仍使用 `/me/posts`。

## 7. 头像要求

沿用前端 4 MiB 上限；允许 JPEG/PNG/WebP 静态图片，实际类型以文件内容识别。服务端限制像素面积、重编码并移除元数据，不接受 SVG、伪装文件和客户端任意存储路径。头像是对外展示资产，上传前界面需说明其可能出现在作者摘要和历史内容中。

旧头像替换后异步清理，不能上传失败就覆盖旧 URL。头像不能挤占正文图片数量或被正文媒体清理任务误删。

## 8. 异常与并发

| HTTP / 错误码（设计） | 处理 |
|---|---|
| 400 VALIDATION_ERROR | 字段或游标无效 |
| 400 SELF_FOLLOW_NOT_ALLOWED | 不可关注自己 |
| 409 USERNAME_TAKEN | 用户名被占用，保留编辑内容 |
| 409 CONTACT_CHANGE_REQUIRES_VERIFICATION | 联系方式需走独立验证流程 |
| 403 INTERACTION_NOT_ALLOWED | 不允许建立关系，不暴露具体隐私设置 |
| 404 USER_NOT_FOUND | 不存在或不可访问，统一提示 |
| 413 PAYLOAD_TOO_LARGE / 415 UNSUPPORTED_MEDIA_TYPE | 文件超限/类型错误 |
| 429 RATE_LIMITED | 显示等待，禁止自动连续重试 |

资料首版采用最后成功保存覆盖同字段的语义，不承诺跨设备编辑合并。按钮请求中禁用，失败恢复服务端已知状态，不通过前端猜测关注计数。

## 9. 验收标准

- [ ] 资料保存后刷新、退出重新登录仍一致，其他用户摘要同步显示新昵称和头像。
- [ ] 用户名并发抢占仅一个成功；非法/超长/控制字符正确拒绝。
- [ ] phone/email 不能通过 PATCH 修改、清空或绕过验证；公开接口不泄露私有字段。
- [ ] 头像大小、真实类型、像素炸弹和旧对象清理通过测试。
- [ ] 自己关注自己被拒；重复/并发关注取消不会产生重复记录或负计数。
- [ ] 粉丝/关注双向文案正确，列表稳定分页，替换 Noop 后关注流和推荐排除生效。
- [ ] 无发布时 postCount 为 0，浏览量未实现显示“暂未统计”，示例数字全部移除。
- [ ] 拉黑、私密、互相关注可见性在主页/动态/列表侧均执行；直连接口不能绕过。
- [ ] 快速切换用户、切账号和请求迟到不会串用资料。

## 10. 依赖与交付

资料与关系存储可先开发；对外开放前必须接入统一会话检查、隐私/拉黑判定和头像存储能力。交付包括数据库增量、F1–F9、前端真实资料加载、统计去硬编码、关系模块回归和权限验收。
