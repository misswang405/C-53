# C-53 设置与隐私需求文档

> 版本：1.0｜日期：2026-10-26｜状态：实施前设计，尚未实现
> 面向：产品、研发、测试。范围：接口清单 H1–H10。
> 配套：[开发文档](../开发文档/设置与隐私开发.md)、[个人资料与关注需求](个人资料与关注需求.md)、[私信与通知需求](私信与通知需求.md)。

## 1. 背景与目标

前端已实现设置页、350ms 防抖保存、黑名单列表、已授权应用列表和数据导出入口，但后端尚无设置与隐私模块。当前 UI 修改不能保护实际资料、动态、评论、关注、私信和通知。

目标：建立服务端权威的设置存储和统一隐私策略，所有业务模块通过策略判断可见性和互动权限。前端设置是操作入口，不是安全边界。

## 2. 功能范围

### 本期包含

- 读取全部设置，按组 PATCH 保存。
- 资料、动态、收藏、关注列表可见性。
- 私信、评论、提及互动权限。
- 个性化内容/广告推荐开关。
- 青少年、长辈、私密模式及互斥/覆盖规则。
- 黑名单查询、移出；补充拉黑接口供资料/成员页使用。
- OAuth/第三方授权记录查询与撤销（仅管理已有授权，不伪造授权来源）。
- 个人数据导出任务创建、状态、下载授权和完成通知。

### 非本期范围

- 管理后台、内容审核、未成年人身份认证、广告平台实现。
- 系统级 Windows/macOS 权限；前端当前“权限”卡片不是后端 OAuth 授权。
- 密码、手机邮箱换绑和登录设备管理；复用认证模块。
- 复杂审计报表、法律保留和跨地区数据驻留策略。

## 3. 设置模型和默认值

```json
{
  "visibility": {
    "profile": "PUBLIC",
    "posts": "PUBLIC",
    "bookmarks": "PRIVATE",
    "followingList": "FRIENDS"
  },
  "social": {
    "messages": "MUTUAL",
    "comments": "EVERYONE",
    "mentions": "FOLLOWING"
  },
  "recommendations": {
    "personalizedContent": true,
    "personalizedAds": false
  },
  "modes": {
    "teen": false,
    "elder": false,
    "private": false
  }
}
```

`PUBLIC/FRIENDS/PRIVATE` 表示公开/互相关注/仅本人；`EVERYONE/FOLLOWING/MUTUAL/NONE` 表示所有人/我关注的人/互相关注/不允许。服务端始终校验枚举，不接受前端中文显示值。

### 模式规则

- `teen` 与 `elder` 互斥；同一请求同时开启返回 409，或按产品明确优先级处理，首版采用拒绝更安全。
- `private=true` 是全局策略覆盖：资料、动态、收藏、关注列表至少降为 PRIVATE；社交权限不能被私密模式绕过。
- 开启私密模式前保存各组原值 `private_mode_backup`，关闭后恢复；若期间用户单独修改设置，应更新备份，不能无条件恢复旧快照覆盖新选择。
- 青少年模式对推荐、私信、评论和可见性施加更严格上限；不能由前端 UI 单独保证。
- 长辈模式只改变展示和提示，首期不降低安全策略。

## 4. 接口需求

以下省略 `/api/v1`，均需登录并采用统一响应。

| 编号 | 接口 | 规则 |
|---|---|---|
| H1 | GET `/me/settings` | 返回完整设置；缺失项返回默认值 |
| H2 | PATCH `/me/settings/visibility` | 整组覆盖，前端当前传四个字段；服务端原子校验 |
| H3 | PATCH `/me/settings/social` | 整组覆盖，校验权限和模式上限 |
| H4 | PATCH `/me/settings/recommendations` | 整组覆盖；广告开关需符合地区/同意策略 |
| H5 | PATCH `/me/settings/modes` | 校验互斥、私密覆盖和恢复规则 |
| H6 | GET `/me/blocked-users` | 分页返回当前黑名单 |
| H7 | DELETE `/me/blocked-users/{userId}` | 移出黑名单，幂等 204 |
| H8 | GET `/me/authorized-apps` | 返回授权应用摘要和 scope |
| H9 | DELETE `/me/authorized-apps/{id}` | 撤销授权，幂等 204 |
| H10 | POST `/me/data-exports` | 返回 202 + taskId/status；异步生成导出 |

为支持设置页实际的“拉黑”动作，增加 `PUT /me/blocked-users/{userId}`，成功返回 204；不纳入 H1–H10 计数。H6/H8 支持 `limit/cursor`，避免无限返回。

H2–H5 默认整组覆盖而非字段合并；缺字段返回 400，避免前端防抖请求把字段意外清空。并发 PATCH 使用 `version` 或 If-Match，冲突返回 409；若前端暂不传版本，服务端可先采用用户行锁并返回最新 settings。

## 5. 隐私策略

- 私密字段默认仅本人：realName、address、birthDate、联系方式、账号授权详情。
- 资料、动态、收藏、关注列表的读取必须经同一个 `VisibilityService`；不能只在前端隐藏。
- 黑名单双向影响：隐藏对方资料/动态/评论/通知目标，阻止新关注和私信；取消拉黑不自动恢复历史关系，产品另行确认。
- 评论/提及按发布者设置和被提及者权限同时校验；拒绝时不得泄露对方设置。
- 推荐开关为内容选择信号，不得关闭必要的安全通知；个性化广告关闭后不能继续基于跨站画像投放。
- 未登录只能看公开内容；FOLLOWING/MUTUAL 关系以服务端真实关系计算。
- 设置变更不改变历史内容的审计记录，但历史内容读取每次按当前策略判断。

## 6. 黑名单、授权和导出

### 黑名单

拉黑前确认用户，成功后解除双方有效关注、禁止新私信、过滤 Feed/评论/推荐；已有会话是否可读由消息策略统一处理。删除/停用用户的黑名单条目不应造成列表异常。

### 授权应用

H8/H9 只服务于真实 OAuth 授权记录。每条返回 `id/appName/scopes/lastUsedAt`，不返回 client secret。撤销需立即使 access/refresh grant 失效，并记录时间；当前仓库没有第三方 OAuth 授权发起实现，不能把 auth_user_agreements 当成 authorized apps。

### 数据导出

H10 创建异步任务，返回 `{taskId,status:"PENDING"}`；完成后通过 G5 通知，通知只含下载任务引用。导出文件短期有效、一次性下载、加密存储并在 TTL 后删除。导出内容按当前用户权限和数据保留策略生成，不包含他人私密消息的超范围副本；失败可重试但不能重复扣费/重复通知。

## 7. 性能、安全和错误

| 场景 | 错误码/行为 |
|---|---|
| 枚举或整组字段错误 | 400 VALIDATION_ERROR |
| 模式互斥/策略冲突 | 409 SETTINGS_CONFLICT |
| 版本冲突 | 409 SETTINGS_VERSION_CONFLICT |
| 无权访问对象 | 404/403，使用统一资源提示 |
| 导出过于频繁 | 429 EXPORT_RATE_LIMITED |
| 存储/队列不可用 | 503，不修改部分设置 |

设置读取 P95 ≤ 150ms；保存 P95 ≤ 250ms。权限判断应避免每条帖子多次查设置，使用短 TTL 缓存并在变更后失效；缓存故障不能将私密内容放开，默认拒绝或回源数据库。

## 8. 验收标准

- [ ] 刷新/换设备后设置保持，非法枚举和缺字段拒绝，不出现半组保存。
- [ ] 私密模式开启后资料、动态、收藏、关注列表、Feed、评论、推荐、私信均不绕过；关闭恢复规则符合定义。
- [ ] teen/elder 互斥且服务端生效，前端绕过 UI 也不能设置非法状态。
- [ ] 拉黑后关注/私信/推荐/资料/动态/通知行为按规则更新，移出黑名单幂等。
- [ ] H8 不把用户协议同意记录显示成第三方应用，H9 能立即撤销真实 grant。
- [ ] H10 返回任务 ID，完成/失败有通知和状态，不返回伪造下载链接；文件过期后不可下载。
- [ ] 设置 PATCH 并发冲突可检测；Redis/数据库异常不产生部分更新或放开权限。
- [ ] A11 未读数和私信/通知策略不因设置页缓存而失效。
- [ ] 日志、导出和通知均不泄露完整联系方式、私信正文或授权密钥。

## 9. 交付依赖

依赖个人资料与关注真实关系、私信/通知模块、动态/互动查询入口和统一认证。交付顺序建议先做设置存储与策略服务，再接入资料/动态/Feed/互动，最后开放黑名单、授权和导出；每个接入点必须有匿名、关注、互关、拉黑、私密模式矩阵测试。
