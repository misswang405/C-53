## 2. 通用约定

### 2.1 地址与前缀

- 前端基准地址：`VITE_API_BASE_URL`，缺省为 `/api/v1`。
- 下文所有路径均省略 `/api/v1` 前缀。
- 请求与响应均为 `application/json; charset=utf-8`，上传接口除外（`multipart/form-data`）。
- 后端成功响应统一包装为 `{ "code": "OK", "data": ..., "requestId": "..." }`；前端 `request` 已自动解包并返回 `data`。
- 后端当前部分兼容路径仍可用（如 `/auth/send-code`、`/auth/token/refresh`），本清单只记录前端正式调用路径。

### 2.2 鉴权

- 登录后携带：`Authorization: Bearer <accessToken>`。
- 普通请求遇 Access Token 失效（401）时，前端调用 `POST /auth/refresh` 并最多重放一次；密码重置 A7 显式禁用自动刷新和重放，验证码错误 401 直接展示。
- 刷新失败（401/403）会清空本地会话并回到未登录状态。
- 后端另会下发 HttpOnly 设备 Cookie，前端不读取，仅由浏览器自动携带。

### 2.3 统一响应

成功（2xx，除 204）：

```json
{
  "code": "OK",
  "data": {},
  "requestId": "req_xxx"
}
```

- 前端实际使用的是 `data`；`code`、`requestId` 主要用于排查。
- 删除、已读等操作返回 `204 No Content`，无响应体。

失败（4xx/5xx）：

```json
{
  "code": "USERNAME_TAKEN",
  "message": "该用户名已被使用",
  "details": [],
  "requestId": "req_xxx"
}
```

- `message` 必须是可直接展示的中文。
- 前端已特判 `TOKEN_EXPIRED`、`SERVICE_UNAVAILABLE`，其余错误直接展示 `message`。

### 2.4 列表与分页

前端 `normalizeList` 同时兼容两种形式：

```json
[ ... ]
```

```json
{ "items": [ ... ], "nextCursor": "xxx" }
```

- 当前前端只传 `limit`，**尚未使用 `cursor` 续页**；清单中保留 `cursor` 参数，便于后续无限滚动。
- 列表为空时返回 `{ "items": [], "nextCursor": null }`。

### 2.5 时间与枚举

- 时间统一为 ISO 8601 UTC 字符串，例如 `2026-10-23T08:30:00Z`。
- 定时发布由前端转成 UTC 后提交，展示时再转本地时区。
- 认证 DTO 当前同时兼容两套字段：正式字段为 `contact` / `contactType` / `channel` / `verificationCode`，前端现行调用使用 `identifier` / `identifierType`；后端 Service 会统一归一化。验证码响应同时返回 `resendAfter` 和兼容字段 `resendAfterSeconds`。

| 枚举 | 取值 |
|---|---|
| 动态状态 `status` | `DRAFT` / `SCHEDULED` / `PUBLISHED` |
| 信息流范围 `scope` | `RECOMMENDED` / `FOLLOWING` / `LATEST` |
| 媒体类型 `mediaType` | `IMAGE` / `VIDEO` |
| 可见性 | `PUBLIC` / `FRIENDS` / `PRIVATE` |
| 互动权限 | `EVERYONE` / `FOLLOWING` / `MUTUAL` / `NONE` |
| 性别 | `PRIVATE` / `MALE` / `FEMALE` / `CUSTOM` |
| 关注关系 | `FOLLOWING` / `FOLLOWED_BY` / `MUTUAL` / `NONE` |
| 验证码场景 `scene` | `LOGIN` / `REGISTER` / `RESET_PASSWORD` |
| 联系方式类型 | `PHONE` / `EMAIL` |
| 分享渠道 | `WECHAT` / `QQ` / `DOUYIN` |
| 消息类型 | `TEXT` |

### 2.6 幂等

- 创建动态：`clientRequestId`（前端每次编辑会话生成一个 UUID）。
- 发送私信：`clientMessageId`。
- 媒体直传确认：可重复调用，重复确认返回相同结果。

**补充说明**

- 验证码前端传大写 `scene`，后端统一转小写，支持 `login` / `register` / `reset_password`。
- 重置必须回传本次 `verificationId`，不回退查找最新挑战；目标不匹配、过期、已消费、未知账号均使用通用验证失败提示。
- 旧 JWT 在过滤器中校验数据库会话，撤销后不再充当认证用户。Redis 清理失败由持久化任务补偿；重置发送和提交限流故障不放行。
- 当前仓库仅有开发验证码发送器。固定码默认关闭，仅显式 dev/test 且无 prod/production profile 时可启用；生产须接入真实发送器。
- 前端传 `identifierType` / `identifier`，后端也兼容 `channel` / `target` 和注册/登录 DTO 中的 `contact` / `contactType`。
- 会话结构：`accessToken`、`refreshToken`、`tokenType`、`expiresIn`、`refreshExpiresIn`、`sessionId`、`user`；登录、注册、验证码登录和切换账号均返回该结构。

- 前端自动保存草稿：首次 `POST /posts`（`status=DRAFT`），后续 `PATCH /posts/{id}`，并用 `version` 做乐观锁。
- 后端创建请求还兼容 `imageIds[]` 和 `scheduledAt` 字段；当前前端发布流程使用 `mediaIds[]`，定时发布单独调用 C5。
- 后端 `PostView` 当前实际返回 `content`、`summary` 和互动计数/状态字段，但尚未返回前端 `normalizePost` 读取的 `title`、`note`、`comments`、`displayTime`。
- `409` 在前端固定提示“草稿已在其他设备更新，请刷新页面后重试”。
- 正文当前为纯文本；`mediaIds` 的顺序即展示顺序。
- 定时发布时间要求至少晚于当前时间 5 分钟（前端先拦截，后端需再次校验）。

- 分享事件用于统计，失败时前端静默忽略，不应阻塞分享。

### 3.5 媒体上传（5）

**补充说明**

- 媒体视图字段：`mediaId`、`mediaType`、`url`、`width`、`height`、`durationMs`、`sortOrder`。
- `url` 为短期签名地址，前端直接用于预览与展示。
- 后端还提供 `GET /media/{id}` 查询当前用户媒体，但该接口不在前端 `api.js` 中调用，暂列为扩展接口。

| H6 | GET | `/me/blocked-users` | 黑名单列表 | 需登录 | 出：用户列表 | ❌ |
| H7 | DELETE | `/me/blocked-users/{userId}` | 移出黑名单 | 需登录 | 出：204 | ❌ |
| H8 | GET | `/me/authorized-apps` | 已授权应用 | 需登录 | 出：`id`、`appName`、`scopes[]`、`lastUsedAt` | ❌ |
| H9 | DELETE | `/me/authorized-apps/{id}` | 解除授权 | 需登录 | 出：204 | ❌ |
| H10 | POST | `/me/data-exports` | 发起个人数据导出 | 需登录 | 出：任务信息（前端忽略，异步通知） | ❌ |

**补充说明**

- 设置项在前端是**防抖自动保存**（350ms），每组单独 PATCH。
- 开启“私密模式”时前端会把可见性全部改成“仅自己可见”，但仍分别调用 H2 与 H5；后端需保证最终一致。
- 青少年模式与长辈模式互斥，前端只拦截 UI，后端仍需校验。

## 5. 当前差异与待补齐项

1. **A1/A7 已补齐代码，部署验收待完成**：已支持重置挑战、密码更新、旧会话撤销和前端挑战回传；须按数据库版本人工执行迁移，配置真实发送器，并完成真实数据库/Redis 并发与浏览器联调。
2. **PostView 字段仍有缺口**：后端 `PostResponse` 已包含 `likeCount`、`likedByMe`、`bookmarkedByMe`、`commentCount`，但没有前端详情页读取的 `title`、`note`、`comments`、`displayTime`；前端会对缺失字段使用空值或空数组兜底。
3. **互动模块已实现**：D1–D9 后端路由均已存在，响应与前端假设一致；评论列表增加了 `limit`、`cursor` 和 `repliesTruncated`。
4. **社区与发现已实现**：B1–B4 后端路由均已存在；B3 支持 `limit`，B2 的 `FOLLOWING` 仍由 Service 层强制登录。
5. **个人资料、关注、私信、通知、设置仍未实现**：前端已定义并调用对应接口，当前后端没有这些 Controller，相关页面操作会收到未授权/未找到响应，需按排期补齐。
6. **后端扩展路由**：`GET /media/{id}` 已实现，但前端当前未调用；兼容路径 `/auth/send-code`、`/auth/token/refresh` 已实现，本清单不重复计数。
7. **游标分页已由后端预留**：前端目前大多只传 `limit`，后端已为 Feed、我的动态、评论、收藏等列表支持 `cursor` / `nextCursor`；后续接入无限滚动时直接复用。
